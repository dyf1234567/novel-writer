# 质量门禁

按操作规模和项目配置成比例地使用门禁。

## 阻断级检查（Blocking）

出现以下任一情况时，阻断接受或发布：

- 分析、TODO、提示词或角色元信息泄漏进正文；
- 已确认的人物、时间线、世界规则或大纲出现矛盾；
- 无效的章节状态迁移；
- 违反用户定义的禁区；
- 预期产物文件缺失或结构无效；
- **每章扫描闭环**：检测器直接读取当前正文；低风险通过，中高风险需润色复检或完成内容绑定的误报复核，未知仍阻断。报告结论须与实际检测一致；一行「轻微」不是接受凭证，冲突结论也不能通过。见下方误报复核流程。

给出最短修复路径。当局部修正足够时，不强制整章重写。

## 降级检查（Degraded）

检索、派生索引、仪表盘或非关键分析器可以降级。降级时：

1. 失败可能是暂态、或索引可安全重建时，重试一次；
2. 使用已记录的兜底方案，例如「最近已接受章节 + 规范记忆」；
3. 记录失败与过期产物；
4. 仅当没有未解决的阻断级事实时才继续。

接受成功后索引重建失败是派生更新降级，不撤回已接受正文与对应记忆。检查 `postprocess_degraded`、`acceptance_result.memory` 及 `warnings`，修复后单独补交记忆或重建索引；旧索引不能当作当前证据，恢复前不宣称项目完全就绪。

## 可选检查（Optional）

在下方默认节奏之外，仅在被要求、被配置或风险证明合理时运行：

- 风格指标审计；
- 多 Agent 编辑审稿；
- 广泛调研；
- 全卷连续性审计；
- 仪表盘生成。

正则与指标产生的是证据，不是最终的文学判决。把反常文笔当作审阅信号，而不是自动缺陷。

`continue-write` 默认将文字指标（字数、对话占比、重复度）作为建议信号；报告仍会记录短章、对话比例、重复度等信号，但它们本身不会使章节门禁失败或触发注水。项目确需数值硬门槛时显式添加 `--strict-prose-metrics`。Beat Sheet 流水线同样为 opt-in，因为其逐 Beat 字数目标是硬约束。

**扫描本身不可跳过**，与 `--strict-prose-metrics` 无关。其分级使用词频、密度和类别数，是启发式信号而非来源鉴定；标签动词少不等于角色声音同质。结构性污染、受保护伏笔和无效状态迁移仍为硬失败，不能通过误报复核豁免。

`--auto-batch-review` 与 `--four-official` 只生成审稿任务文件。它们不派发 Agent、不记录编辑判定；在审稿人真正完成前，任务一律报告为 pending。

## 默认审查节奏（含去AI味，默认启用）

1. **每章 —— 针对性连续性检查 + 扫描闭环。** 接受前，将草稿对照相关已接受段落和已确认的人物、时间线、世界规则、伏笔状态，核查本章变更过的事实与因果链，记录未解决冲突。完成正文后扫描；中高风险针对性润色或逐项误报复核，未知不得接受。`chapter_gate_check.py` 与手动接受入口核验实际正文。接受后同步相关记忆与索引。
2. **每 10 个已接受章节 —— 创作检查点与风格复核。** 写下一章前，与用户或指定审稿人共读近期代表性文段，回顾方向、人物主动性与节奏。将文笔与本书已确认的风格和角色声音比对；配置了作者风格包时使用其选定语系与抽象特质。没有可靠风格基线时，如实报告该局限并评估可观察的一致性。文字指标仍为建议性质。检查点决策与复核记录一并保存；不得为了让漂移消失而更新风格基线。
3. **每完成一卷 —— 全卷审计与多 Agent 审稿。** 用 `volume_audit.py` 汇总卷级证据；然后分批审阅正文与相关状态。具备协作能力时，派发只读审稿人分别负责连续性、人物与因果、结构与节奏、文风，提供项目路径、章节范围、相关状态与审稿问题；每位审稿人阅读原文并返回带章节引用与摘录的发现。根 Agent 裁决冲突、处理修改、记录卷判定后方可推进。
4. **重大剧情决策 —— 红队审查。** 当用户、已批准大纲或宿主识别出角色死亡、身份揭露、世界规则突破等不可逆变化时，接受前审查其铺垫、动机、因果支撑、后果与替代方案。可行时使用只读红队 Agent。尊重已确认的结局与刻意的创作选择；不仅因「出乎意料」而否决意外。

协作工具不可用时，宿主按相同项目逐项审阅，并明确报告「独立多 Agent 审稿未运行」。任务生成在审稿真正完成前一律报告为 pending。已确认矛盾与用户硬约束必须修正；风格偏好仅作为建议交作者决定。记录写入现有编辑/检查点产物，不新增审稿数据库或配置层。

## 人物与因果审查

人物与因果审查时，对相关选择套用 [character-tension.md](character-tension.md)：动机与知情状态、可信的冲突与铺垫、双方的主动性、相称的代价、延续的后果。重大剧情红队需考虑合理替代方案与缺失铺垫。返回基于段落的发现与窄幅修复建议；缺卡、创伤、面具、镜像人物或悲剧结局不构成失败。这些是宿主语义检查，不是新的数值门禁，也不增加默认审阅频率。

## 误报复核与接受边界

先阅读正文与 `detect` 输出的全部命中项。真正重复或不合语境时润色；符合已确认声音的表达可保留。不得只为了通关而填写「都是误报」。复核理由需覆盖各命中类别并说明对应文段与创作意图；这仍依赖审阅者判断，不是脚本自动语义审稿。

```text
python scripts/text_humanizer.py detect --chapter-file <正文路径>
python scripts/text_humanizer.py review --project-root <项目目录> --chapter-file <03_manuscript/第N章.md> --reviewer <审阅者> --reason <逐项保留理由> --confirm FALSE_POSITIVE
```

复核写入该章既有门禁目录的 `ai_flavor_review.json`，只豁免当前正文的这些启发式命中，不免除扫描或其他门禁。正文、检测结果或检测器版本改变后必须重审；维护检测规则时须递增 `ai_flavor_state.DETECTOR_VERSION`。随后用 `continue-write --chapter-file <章节路径>` 重生成当前正文的各报告并运行门禁（已有有效复核不会触发自动润色），再接受。不要手改报告标签来通关。

`novel_chapter_writer` 的生成与润色始终不提交正式记忆，旧配置 `auto_update_memory: true` 也不能绕过。`canonical_state.py accept` 在接受成功后更新 `recent.md` 中按章号管理的正文摘记；重试或修订替换同章区块，不重复追加，不自动认定摘记中的事实。保留用户手写和旧版无标记摘要；曾被旧流程污染的记忆须人工核对，不自动删除。记忆写入失败会明确返回降级状态，修复后重跑同章接受可补交。

旧项目显式接受仍需扫描和审阅。已有历史接受记录不会因升级被批量撤销；修订或重新接受时执行新检查。旧稿没有其他门禁文件时，由指定审阅者完成其他语义检查；已有门禁文件时不能忽略失败或过期结论。后续索引仍需重建。

一次 `continue-write` 的 AI 风格自动润色最多调用模型两次，报告重建和自动重试共享同一预算，生成器内部不另开隐藏润色轮次。扫描始终继续；预算耗尽而命中未闭环时停止模型调用并阻断接受，等待人工润色或有效误报复核。报告与结果中的累计调用数可核查。此上限仅指 AI 风格润色，不包含初稿生成或显式启用的 Beat、节奏重写；独立再次启动续写是新任务，重置预算。

## 汇报

返回紧凑结果：

- `blocking`：阻断接受失败的项；
- `degraded`：失败的子系统与所用兜底；
- `optional`：运行过的可选检查与发现的信号；
- `accepted`：规范记忆是否已更新。
