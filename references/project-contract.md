# 项目契约

撰写、连续性查阅，或任何改动持久项目状态的操作，读本参考。

## 事实优先级

事实冲突时按以下优先级裁决：

1. 用户的显式纠正或确认；
2. 已接受的正文章节；
3. 已批准的大纲与世界规则；
4. 结构化追踪器与图谱状态；
5. 生成的章节摘要；
6. 检索结果与模型推断。

绝不用低优先级的推断覆盖高优先级的来源。

## 项目区域约定

既有项目可能使用不同命名。按用途映射，而不是强迫迁移：

- 规划：前提、大纲、卷与章节锚点；
- 记忆：人物、世界状态、时间线、伏笔、章节摘要；
- 正文：已接受章节的正文；
- 检索：由已接受正文派生的索引与段落元数据；
- 编辑：审计报告、修复计划、未入规范的草稿。

只创建所选工作流需要的目录。保留用户的额外文件。

## 章节状态迁移

使用显式迁移：

```text
planned -> drafted -> reviewed -> accepted -> indexed
                   \-> needs_revision
```

- `drafted` 的正文不是规范记忆。
- `accepted` 需要用户接受、或项目配置的自动化策略加全部阻断级检查通过。
- 只有已接受章节进入持久摘要、图谱与检索索引。
- 已接受章节的修订会使该章的派生摘要、图谱事实与检索条目失效，直到重建完成。

`continue-write` 以接受成功为提交边界。此前失败且启用回滚时恢复草稿；此后索引失败或后处理异常，不恢复旧正文而留下新记忆，保留已接受正文及其凭证与摘记，并报告 `accepted`、`acceptance_result`、`postprocess_degraded` 和恢复步骤。`ok: true` 不等于派生更新全部完成，须检查降级状态；后处理异常仍可返回 `ok: false, accepted: true`。记忆补交用同章 `accept`，索引恢复用相应 `build`。

## 连续性上下文

优先使用从相关状态装配的紧凑上下文，而不是通读整个项目。包含：

- 当前锚点与目标；
- 近期已接受章节摘要；
- 活跃人物及其别名、位置、能力与关系；
- 时间线约束；
- 未解决与已到期的伏笔；
- 支撑当前实体或剧情线的检索文段；
- 大纲变更引起的级联警告。

检索结果与规范状态冲突时，把冲突摆出来，而不是把两个版本调和在一起。

直接读取历史正文和近期摘要也必须核验内容绑定的接受状态，不只是索引如此。字数超过 500 的截取过程不得改写章节号；文件名补零不影响章号识别。旧或过期元数据不作为已接受章节的摘要来源，回退到当前已接受正文；同章上下文缓存随正文、接受状态及相关项目输入变化而失效。

续写成功缓存绑定全部有效 CLI 配置、项目策略/记忆、正文与接受凭证、复核记录和检测器版本；启用严格指标或改动这些输入后重跑，不沿用旧通过结论。旧格式缓存不复用，派生更新降级不写入成功缓存。`--force-run` 仍可显式要求完整重跑。

## 安全变更

- 每个已接受章节之后做窄幅更新。
- 大范围修订大纲前，界定受影响章节范围并保留可恢复的先前状态。
- 只重建受本次变更影响的派生产物。
- 可选或派生更新失败，不得损坏已接受正文。
- 绝不在小说章节工作流中编辑用户的原作语料或外部作者包。
